# POC-02: input-to-UI Automation correlation

## Purpose

POC-02 tests whether low-level mouse clicks and keyboard events can be
captured briefly and correlated with the relevant UI Automation element,
focused control, top-level window, and owning process.

This is an isolated research harness. It is not the product recorder, action
model, target resolver, or replay engine.

## Design

1. A dedicated hook thread installs `WH_KEYBOARD_LL` and `WH_MOUSE_LL` only
   while the experiment runs.
2. Hook callbacks copy only the native event fields into a bounded queue and
   return immediately. They do not query UI Automation or write files.
3. A separate MTA UI Automation worker drains the queue.
4. Mouse button events use the hook coordinates with `WindowFromPoint` and
   `AutomationElement.FromPoint`.
5. Keyboard events use the foreground window and
   `AutomationElement.FocusedElement`.
6. The worker records fresh element snapshots, process/window identity,
   timestamps, injection state, queue drops, and failures as JSON.
7. The scripted test driver uses `SendInput` to generate reproducible input.
   Such events are marked `injected: true`; this is intentionally visible in
   the report and is not claimed to be indistinguishable from physical input.

## Run the reproducible test

On Windows with an interactive desktop session:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-Poc02.ps1
```

The script builds the complete Release solution, launches both fixtures,
starts the correlation harness, sends a button click, text focus plus Unicode
keyboard input, and a checkbox click, then validates the generated reports.

Reports are written to:

```text
artifacts/poc-02/wpf-correlation.json
artifacts/poc-02/winforms-correlation.json
```

## Acceptance criteria

- Both fixtures produce at least one correlated event.
- No bounded-queue input events are dropped.
- Both fixtures produce mouse events with UI Automation target elements.
- Mouse correlation identifies `InvokeButton`, `ValueTextBox`, and
  `ToggleCheckBox`.
- Both fixtures produce keyboard events with a focused UI Automation element.
- Keyboard input correlates to `ValueTextBox`.
- Target-process events contain window/process identity.
- Target-process events contain no correlation failure.
- Reports contain UTC and monotonic timestamps.
- Scripted mouse and keyboard events are both marked as injected.

## Manual mode

The harness can observe real user input for a bounded period without scripted
input. Start a fixture, find its process ID, then run:

```powershell
dotnet run --project .\src\TeachMeOnce.InputCorrelation\TeachMeOnce.InputCorrelation.csproj --configuration Release -- `
  --pid <fixture-process-id> --duration-seconds 10 --output artifacts/poc-02/manual.json
```

The report includes `injected: false` for physical events and
`injected: true` for events generated by `SendInput`.

## Known limits

- The hook is global to the current interactive desktop while installed;
  POC-02 records target-process association rather than silently discarding
  other desktop input.
- UI Automation provider behavior can make a point resolve to a text child;
  the worker promotes that element through the control-view ancestry to the
  nearest actionable element with an automation ID or recognized control type.
- This experiment does not group events into gestures, persist workflows, or
  replay any action.

## Sources

- [Windows hooks overview](https://learn.microsoft.com/en-us/windows/win32/winmsg/about-hooks): low-level keyboard/mouse hooks can monitor input, but global hooks have system overhead and should be short-lived.
- [UI Automation threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading): UI Automation calls should be made from a separate MTA thread when the client owns a UI.
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): synthesizes keyboard and mouse input and is subject to UIPI.
- [GetCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos): Windows screen coordinates are used for pointer correlation.
